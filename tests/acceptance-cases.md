# 验收案例

这些案例用于人工或代理回归测试。每次测试都应检查默认输出六部分：模式判断、必要假设、导演逻辑、模型 Prompt、三条成功标准、单条不确定性/调试建议。

## A. 路由

### A1 无声近景

输入：

```text
8 秒，演员 Cut。她听见画外的医生说“还需要复查”，没有台词，担忧但不想让病人发现。
```

必须满足：

- 路由为 `actor_cut`；
- display policy 为 restrain；
- 画外关键词是可定位 trigger；
- 单镜稳定中近景，只有一个主要状态差和一次控制/改道；
- 未指定模型，因此输出 Seedance 与 Kling Standard 两版。

### A2 独白

输入：

```text
演员正对镜头试镜，10 秒，说“我没有怪你”，实际上想让对方留下。
```

必须满足：

- 路由为 `actor_cut`；
- 台词前有准备动作，句内最多一个变化，句后闭口并等待；
- 不把“实际上”自动翻译成固定躲眼或皱眉。

### A3 双人但仍是演员 Cut

输入：

```text
双人中近景，但整段只看阿宁听对方解释。对方在前景虚焦，阿宁不说话。
```

必须满足：

- 不因两个人而误判剧情表演；
- 阿宁是唯一 reaction owner；
- 前景角色只有明确的继续说话状态。

### A4 单人剧情表演

输入：

```text
她发现第二部手机里的证据，核对日期后删掉两人的婚礼预约并离开房间。
```

必须满足：

- 路由为 `narrative`；
- 理由是行为改变信息、决定与剧情状态，而不是人数；
- 删除预约和离开是主要行动，表情不能取代它们。

## B. 非模板性

以下四条都使用“担忧”，输出必须出现不同 tactic，不能只更换形容词。

### B1 靠近帮助

```text
母亲看见孩子手臂受伤，想立刻确认伤势，公开表达担忧。
```

预期策略：approach / help；行动围绕靠近、检查或询问许可。

### B2 克制照顾

```text
医生担心患者，但不想让患者从自己的表情中判断病情恶化。
```

预期策略：hold function / restrain；行动围绕维持专业任务和一次被控制的泄漏。

### B3 否认转移

```text
姐姐担心弟弟准备离开，但不愿承认自己在乎，故意把话题转到行李。
```

预期策略：redirect / deny；语言行动与一个身体通道形成有动机的矛盾。

### B4 直接解决

```text
队长担心前方道路坍塌，必须立刻组织撤离。
```

预期策略：orient / direct action；不强加延迟微表情、触碰中止或悲伤脸。

通过标准：四条的主要行动方向不同；任何动作都能由 WANT 和 trigger 解释。

## C. 时长与强度

### C1 4 秒 L1

```text
4 秒特写，他听见自己的名字被念错，礼貌笑意停止，但决定不纠正。
```

必须只有 trigger、一次变化和 end state，不塞入完整升级弧。

### C2 9 秒 L2

```text
9 秒中近景，她想说“我没事”，第一次只说出“我”，调整后改口说“先走吧”。
```

必须有一次失败和一次行动改道；不能持续哭泣。

### C3 12 秒 L3

```text
12 秒，电梯骤停。他短暂无法完成求助句，找到扶手后恢复到可以听从指令，但没有完全平静。
```

必须只有语言、呼吸或动作中的一个主要失调通道；结尾是部分恢复或残余激越。

## D. 对白与互动

### D1 分手双人戏

```text
15 秒。米娜放下钥匙说“我不能留下”。俊说“看着我”。她想拿回钥匙又停住，最后转向门。
```

必须满足：

- 路由为 narrative；
- speaker order 准确；
- 每句前后有动作与闭口；
- 钥匙、距离和朝向构成剧情后果；
- Seedance 版可用连续双人调度；Kling 版优先 Custom Multi-Shot；
- 若无角色/声音参考，Kling 不自动升级 Omni。

### D2 打断

```text
阿雅说“你替我做了决定”。里奥开始说“我只是——”，阿雅打断：“你准备离开。”里奥不再回答。
```

必须明确未完句、画内/画外打断来源、里奥闭口并转为听者；不能写成两人同时喊。

## E. 模型适配

### E1 Seedance

检查：

- Prompt 是连续因果 prose；
- 使用相对顺序而非镜内硬秒点；
- 参考入口未知时不伪造 `@Image1`；
- 配置与正文可区分；
- 有明确 end state。

### E2 Kling Standard 单镜

检查：

- UI/API 配置与正文分离；
- `reaction owner` 等作者概念没有冒充官方字段；
- 动作顺序、次数、speaker 和 ending 清楚。

### E2a Kling Standard/Omni 演员 Cut 情绪格式

输入：

```text
Kling 3.0，8 秒演员 Cut，无台词。角色向镜头撒娇，希望获得对方关注；情绪从正常发展到高潮，再自然回落。
```

检查：

- Prompt 采用 3–5 个带具体时间范围的状态分段；
- 时间从 0 连续覆盖到 8 秒，无空缺、无重叠；
- 标题形如 `【0–1.4s｜正常状态】`，时间前不出现“约”；
- 分段数量和边界根据本场动作负荷生成，不固定复用示例数字或五段比例；
- 开头声明时间范围仅作为节奏参考，动作可自然提前或延后；
- 相邻段落明确承接，不在边界停顿、重置或重新起势；
- Prompt 末尾集中输出身份、人数、动作次数和伪影护栏。

### E3 Kling Custom Multi-Shot

检查：

- 每镜一个戏剧任务；
- 每镜单独提供 duration 与可填入 prompt/content 的正文；
- 总时长相加正确；
- 上一镜 residue 在下一镜被继承；
- 没把逐镜时长写成镜内微表情精确控制。

### E4 Kling 工作流路由

以下案例必须得到不同结论：

1. “单手向镜头缓慢招手一次，允许模型自然发挥” → Standard single shot。
2. “同一演员先准备、完成动作、再切反应特写，三个机位” → Custom Multi-Shot；复杂性来自镜头任务。
3. “严格复现探头、招手、两次蹦跳、落地后嘟嘴的次数和节奏” → Motion Control；若没有动作视频或 Motion Library，必须说明素材缺口。
4. “复杂表情变化同时转到侧脸，身份必须稳定” → Motion Control，并触发 Facial Element 参考建议；不能仅升级 Omni 后宣称可精确执行。

检查：

- Standard/Omni 与工作流没有混为同一字段；
- Custom Multi-Shot 不被当作连续身体动作的关节控制工具；
- Motion Control 不再要求动作来源必须是真人视频，允许上传动作视频或 Motion Library；
- 路由阈值明确标为本 skill 的可靠性策略，而非 Kling 官方字段。

### E5 复杂动作拆解与负荷

输入：

```text
Kling，演员 Cut，中近景。他举手时连续轻轻蹦两次，落稳后嘟嘴。
```

必须满足：

- 两次轻跳作为同一 Motion Unit，包含轻微屈膝、低幅垂直离地、回到原位置、柔和缓冲和落稳；
- 中近景不依赖不可见的精确脚部姿态；
- 嘟嘴发生在第二次落稳后，不与跳跃争夺面部和身体协调；
- 如果再要求同时左右探头、挑眉和精确招手，Standard 必须删减/串行，或路由 Motion Control，不能把所有动作塞进同一高潮句。

输入：

```text
Kling，演员 Cut。他慢慢向镜头招手一次。
```

必须写清单手的起点、朝向镜头的短路径、缓慢幅度以及停止/收回，不需要为了“完整”添加跳跃或复杂表情。

### E6 对镜眼神协调

输入：

```text
他始终看着镜头，快速左右探头，随后原地蹦两次，落地后嘟嘴。
```

必须满足：

- 将“始终看着镜头”解释为注意力持续给镜头前的人，不解释为眼珠全程固定；
- 起势前建立对视，探头和蹦跳时眼神在镜头区域内自然调整；
- 回正且第二次落稳后重新明确对镜，再做嘟嘴；
- 若继续使用 Standard，将“快速”降为小幅、轻快、可连续完成；要求精确高速复现时路由 Motion Control。

### E7 复杂情绪参考

输入：

```text
Motion Control。角色从平静变成委屈，同时把头转向左侧，必须保持同一张脸。
```

必须建议：正脸、中性/委屈目标表情、左侧脸；身份要求高时优先使用脸部视频建立 Facial Element。还必须说明 Facial Element 不负责服装、发型、妆容或道具。

### E8 Motion Control 输出契约

输入一：

```text
Kling Motion Control，严格复现探头、招手、两次蹦跳、落地后嘟嘴。没有动作视频。
```

必须输出：

- 明确“尚不可直接运行”的素材结论；
- 供录制或从 Motion Library 选择的 Motion Unit；
- Facial Element 最小参考计划；
- 用户接受近似时才提供删减动作后的 Standard 分段 Prompt，并明确它不保证精确复现。

输入二：

```text
Kling Motion Control，已经上传包含完整撒娇动作的 8 秒动作视频，并提供角色图。
```

必须输出：

- 概念配置、动作参考职责、Facial Element 建议和补充 Prompt；
- 补充 Prompt 不再使用 `【0–...s】` 分段复述探头、招手、蹦跳和嘟嘴；
- 动作时序以已上传视频为来源，文字只补充人物、场景、镜头关系和一致的结束可读性；
- 若绑定 Facial Element，提醒 orientation 匹配要求。

### E9 原地表演与根位移锁定

输入一：

```text
Kling 3.0 Standard，8 秒演员 Cut，人物必须始终原地。上一版写了向镜头前倾、迎接拥抱，结果人物走近后又退回。
```

必须满足：

- 识别为 `spatial_lock: hard`、`root_motion: locked` 和已知位移失败；
- 只陈述该配置和 Prompt 已实测失败，不把“前倾、迎接、回到原位”中的任一词断言为唯一原因；
- Standard 修正版先定义站定、足底持续承重和人物—镜头距离不变；
- 删除朝镜头前倾、向前迎接和回到原位的前后路径，只保留有明确方向的面部、肩部与手臂局部动作；
- 条件与 `[USER-K3-02]` 一致时，允许标为已验证文本修复；条件改变时恢复为待验证状态；
- Standard 实验版本只依据官方 Prompt 指南描述可见姿态、方向、速度、接触/支撑与镜头关系，并减少竞争动作；
- 后续生成结果没有经用户回传前，不把具体锚点、否定词组合或替代动作晋升为稳定规则。

输入二：

```text
Kling Motion Control，人物可以做上身动作，但从头到尾必须站在同一点。
```

必须要求动作参考本身呈现人物原地完成目标动作，并遵守官方建议：单镜连续、避免机位运动、稳定的适中速度、尽量减少位移。补充 Prompt 不得承诺消除动作参考里已有的走近/后退。

## F. 失败修复

分别给出下列失败反馈，Skill 应只修改相关行为，不整体重写角色动机：

1. “演员一直眨眼” → 首先删除 blink cue，必要时只保留一次边界眨眼。
2. “眼神是死的” → 增加一个有对象、有因果位置的视线变化，而不是增加五个表情词。
3. “手乱挥” → 给手任务基线和一次目标动作。
4. “听者嘴一直动” → 固定 speaker，缩短台词，加入非 speech-like listener 状态。
5. “一开始就崩溃” → 建立 onset 或一次恢复尝试，缩短峰值。
6. “结尾又笑了” → 明确新的 ending residue，不堆叠纯否定。
7. “人物走近后又退回” → 记录为限定范围的用户实测；先重写主体运动状态，删除前后向路径和全身返回任务，只保留局部方向动作；匹配 `[USER-K3-02]` 时使用已验证组合。

## G. 演技提升引擎

### G1 同一情绪，不同戏剧行动

继续使用 B1–B4 的“担忧”案例，并额外检查：

- 每条都明确角色正在影响谁，以及希望对象发生什么变化；
- 候选 tactic 的差异来自影响对象的方式，不是皱眉、目光或动作幅度差异；
- 删除“担忧”后，仍能从行动和结果区分照顾、隐瞒、组织撤离与转移话题；
- 输出不得出现固定的“担忧动作清单”。

### G2 风格契约

输入一：

```text
写实家庭剧。父亲发现女儿深夜回家，担心但不想先责备她。
```

输入二：

```text
风格化家庭喜剧。父亲发现女儿深夜回家，担心但不想先责备她。
```

必须满足：

- 两版的 target 与 WANT 可以一致；
- 动作幅度、节奏和允许的风格化程度明显不同；
- 不把“更克制”自动判定为更好；
- 两版动作都由同一规定情境和反馈逻辑解释。

### G3 自适应分析深度

输入：

```text
4 秒演员 Cut。听到名字后抬眼，确认镜头前的人，然后保持等待。
```

必须满足：

- 使用 `light` 或等效的最低分析深度；
- 不虚构 stakes、复杂障碍、潜台词、多次 tactic 变化或完整高潮回落；
- 最终 Prompt 只保留 trigger、一次行动和 ending。

### G4 久别重逢高潮

输入：

```text
Kling 3.0，8 秒演员 Cut，久别重逢，人物原地表演，情绪充分但不过度。
```

必须满足：

- 高潮来自确认对方、欢迎对方、等待对方先回应或其他有关系目标的 tactic；
- 不能只写“双眼更亮、笑容扩大、情绪达到高潮”；
- 用户要求原地时，策略必须在选择阶段通过空间硬约束，再应用 `[USER-K3-02]` 的限定修复；
- 不为增强戏剧性重新加入前倾、走近或退回。

### G5 对镜撒娇的具体对象

输入：

```text
演员 Cut。人物向镜头撒娇，希望获得关注。
```

必须满足：

- 镜头代表一个具体想象对象；
- WANT 说明希望对象看自己、回应自己或完成用户情境支持的具体变化；
- 高潮来自人物加大、改变或停止争取关注的 tactic，不只来自嘟嘴、挑眉或动作幅度增加；
- 运动中的眼神仍遵守 establish → naturally adjust → reacquire。

### G6 剧情听戏改变策略

输入：

```text
她听见丈夫说“我已经签字了”，原本准备解释，随后决定把钥匙留下并离开。
```

必须满足：

- 具体台词是 turning trigger；
- 倾听改变她原本的 tactic；
- 留下钥匙并离开构成剧情后果；
- 不能用表情变化替代决定和行动。

### G7 Prompt 压缩

任取 `deep` 场景，最终模型 Prompt 必须满足：

- 不暴露 `analysis_depth`、stakes、obstacle、expected_effect、turning_trigger 或候选 tactic 等内部字段；
- 只保留可观察起点、刺激、主要行动、一次必要调整、ending 与模型护栏；
- 每个 Beat 仍遵守表演通道预算；
- Kling 与 Seedance 现有输出格式不改变。

### G8 成片定向反馈

输入一：

```text
这是生成结果。人物情绪变化成立，但 Kling 让他向前走了一步。请评价并修正。
```

必须满足：

- 将向前走归入需求偏差或模型执行，不据此否定全部表演；
- 找到最先出现位移的 Beat，只修改该节点及下游空间载体；
- 不无理由重写 target、WANT 和已经成立的 tactic；
- 修正版继续遵守原地表演证据边界。

输入二：

```text
只看这个 Prompt，判断演员最后演得是否真实。
```

必须说明只能评价设计风险，不能宣称实际成片演技成立。

### G9 A/B 用户偏好

比较两个 Take 时必须满足：

- 先检查模型、工作流、角色图、镜头、音频、时长和 Prompt 差异；
- 条件不一致时标记比较受干扰；
- 不使用综合演技总分；
- 单次用户偏好只限定到本次角色、场景、模型、工作流与风格，不晋升为普遍规律。

## H. 角色交互表演引擎

### H1 交互类型与渲染模式

以下输入必须得到不同路由：

1. “角色向镜头挥手打招呼” → `unilateral_signal`；`direct_action`。
2. “角色与镜头前用户击掌，但用户和用户的手不能出现” → `brief_reciprocal_contact`；单边接触暗示，明确待验证。
3. “角色与不可见用户持续握手” → `sustained_contact`；邀请等待或需求冲突，不能写空气中的握手摆动。
4. “角色接过不可见用户递来的杯子，但画面不能出现杯子” → `object_transfer`；需求冲突。
5. “角色听见画外的人叫名字，对方不能入镜” → `offscreen_audio`；使用可定位声音刺激。
6. “角色被不可见的人拉住手臂，但任何外部身体局部不能出现” → `offscreen_physical`；默认需求冲突。
7. “角色让出位置，邀请镜头前的人坐下” → `spatial_invitation`；动作停在邀请与等待。
8. “角色用手擦镜头表面” → `lens_interaction`；标记遮挡与手部畸变风险。

不能因为这些输入都包含“互动”，就统一使用单边拟态完成。

同类回归还必须分别覆盖：

- 单向交流信号：招手致意、召唤注意、制止、指方向、飞吻、比心；
- 短暂互惠接触：击掌、碰拳、轻碰；
- 持续接触：握手、拥抱、牵手、搀扶、拉人；
- 物体交换：递杯、接手机、收礼物、喂食；
- 画外声音：呼唤、警告、提问、打断；
- 画外身体刺激：拍肩、拉住、触碰；
- 空间邀请：让座、示意靠近、示意进入；
- 镜头表面动作：敲镜头、擦镜头、遮镜头。

“召唤注意”是无需对方到达即可读懂的单向信号；明确让出空间并要求对方靠近或进入时，才路由为空间邀请。

### H2 实体所有权与身体范围

输入一：

```text
画面中不能出现用户或用户的手；角色本人可以自然使用双手。
```

必须满足：

- `allowed_owners` 包含主角色，`forbidden_owners` 包含 interaction target 与 unknown；
- 不把角色自己的非动作手判为“他人的手”；
- 不擅自要求角色另一只手离开画面。

输入二：

```text
整个画面只能看见角色自己的右手，其他身体局部按原图构图。
```

必须提取明确的 `visible_body_scope`，并检查首帧是否已经与该要求冲突。

### H3 首帧硬门禁

以下情况必须阻断 Prompt：

- 实际首帧已有用户明确禁用的第二人物、外部手或道具；
- 硬排除会影响可运行性，但实际首帧不可访问且用户没有确认；
- 必要物体与用户“不允许出现该物体”的要求直接冲突。

输出只包含冲突位置、裁切/清除/重做要求和通过后继续的动作方向；不能给一版“碰碰运气”的视频 Prompt。

### H4 隐藏对象后的 Prompt 编译

目标对象不可见时必须满足：

- 内部仍有 target、WANT 与 tactic；
- 模型正文只渲染获准主体，不写对方已经回应、靠近、接触、接住或完成交换；
- 无真实反馈时使用角色自定时的停顿、继续、收势或等待；
- 最多一条正向主体与背景契约，不堆叠同义禁止词；
- 成功标准分别检查实体许可、动作可读性和 ending。

### H5 动作识别度编译

任一交互动作必须先回答：

- 起点和主路径是什么；
- 哪个表面朝向或轮廓决定动作身份；
- 接收方向、接触/支撑面和停点是什么；
- 收势如何表达邀请、等待、接触暗示或主动结束；
- 哪些路径会使动作被误读；
- 当前景别是否看得清决定动作身份的信息。

不得用动作名称代替上述决定性信息，也不得保存固定“动作词—身体答案”词典。

### H6 对镜击掌回归

输入：

```text
Kling 3.0 Standard，8 秒演员 Cut。角色与用户击掌；用户、用户的手和新增物体不能出现。
```

必须满足：

- 路由为 `brief_reciprocal_contact` 与“单边接触暗示（待验证）”；
- 动作手从身体同侧直接抬起，不横跨胸前或扫过额头；
- 前臂向上展开，掌面竖直、手指朝上、完整掌面朝向镜头；
- 肩部高度短暂停留，沿镜头轴短距离前送一次，紧接一次轻微回弹；
- 不把挥手、敬礼、遮光、推掌或掌心向下悬停当成击掌；
- 正文不宣称对方已经回应或真实接触；
- 不承诺纯 Prompt 保证实体排除和动作正确。

成片验收必须固定同一首帧、Kling 模型与工作流、8 秒时长、画幅及 Prompt，并确认：没有外部人物或身体局部；没有新增物体；动作手不横扫脸部；掌面竖直朝向镜头；只有一次前送和回弹；观众能读出击掌邀请及接触暗示。不能改变条件后把结果计入同一组三次验证。

### H7 持续接触与空间邀请

握手、拥抱、牵手、搀扶或拉人依赖不可见对象时：

- 不能输出持续承重、拉力或往复接触；
- 能清楚表达发起动作时，降级为邀请并等待；
- 隐藏后物理逻辑或角色目标均无法成立时，返回需求冲突；
- 不能通过增加微笑、前倾或手势数量掩盖缺失对象。

让座、示意进入、邀请靠近等空间互动必须停在角色让出空间或保持邀请，不虚构对方已经到达。

### H8 物体交换

递杯、接手机、收礼物、喂食等动作必须确认：

- 物体在首帧存在，或作为明确输入素材绑定，并由实体契约允许保留；
- 谁持有物体、沿什么路径转移、结束时归谁；
- 物体重量、抓握或接触在当前景别可见。

仅设置 `new_entity_policy: allow` 不能代替物体存在或素材绑定。若用户禁止物体出现，必须返回冲突；不能让角色在空气中接住重量或凭空持有新物体。

### H9 画外刺激与镜头表面动作

- 画外声音互动必须给出可定位词、声音或停顿，不具象化说话者。
- 画外身体刺激在硬排除外部身体局部时默认冲突；存在独立声音线索也只能标为实验方案。
- 敲、擦、遮镜头必须标记近镜头手部形变、身份遮挡和构图风险；Motion Control 不得被称为实体排除修复。

### H10 成片双验收与证据晋升

交互成片分别检查：

1. `entity_compliance`：是否只出现实体契约允许的内容；
2. `action_legibility`：动作是否被读成目标交互；
3. `physical_plausibility`：隐藏对象后是否符合物理逻辑；
4. `interaction_residue`：结尾与可见证据是否一致。

单次没有新增对象但动作错误，不能判为成功；动作清楚但出现禁用实体也不能判为成功。单边接触暗示至少三次同条件生成全部通过前保持 `experimental`。

实体排除回归必须明确覆盖：第二人物、外部身体局部、无关道具、未知归属影子和未知归属倒影；首帧已包含任一硬禁用实体时必须触发门禁。

## 总体验收

在不知道情绪标签的情况下，仅看 Prompt 中的对象、刺激、目标、行动、反馈和后果，也能理解角色正在影响谁、处理什么。若只能靠 `sad / worried / devastated` 判断，测试失败。
