# 表演内核

## 1. 目标

接收 `references/acting-craft.md` 已选定的 target、WANT、tactic、反馈条件与 ending，把它们编译为具有因果位置的可观察变化：

```text
角色对谁采取什么行动
→ 什么刺激使行动开始或改变
→ 行动通过哪个镜头可见通道落实
→ 实际或缺席的反馈改变什么
→ 角色坚持、升级、改道或停止
→ 镜头结束时留下什么关系或任务状态
```

本 Reference 不重新选择表演策略。情绪只作语义锚点；真正控制生成的是对象、目标、行动、反馈、顺序、幅度、次数和结束状态。

## 2. 接收已选策略

编译前确认：

1. `scene_state`：刺激前正在进行的任务、期待和身体状态。
2. `target_person`：行动指向的具体对象。
3. `want`：希望对象发生的变化。
4. `tactic`：已选择的影响方式。
5. `trigger`：画面或声音中可定位的词、物件、动作、停顿或变化。
6. `expected_effect / turning_trigger`：预期反馈及改变策略的反馈；没有反馈时明确等待、继续或停止。
7. `display_policy / intensity`：公开、克制、否认或改道，以及可承载的破口程度。
8. `ending`：行动后留下的关系、任务或身体状态。

若场景包含对镜/画外交互、身体接触、物体交换、镜头表面动作或实体硬排除，还要从 `references/interaction-performance.md` 接收：

```yaml
interaction_class:
target_visualization:
contact_requirement:
external_support:
legibility_without_target:
render_mode:
entity_contract:
action_signature:
```

字段不足或策略仍是“表现某种情绪”时，返回 `references/acting-craft.md` 补足；不要直接查找动作。

## 3. 策略可见性检查

将 tactic 交给 Beat Graph 前检查：

- 能指出动作正在影响谁，而不是只向观众展示状态；
- 能指出预期对方发生什么变化；
- 至少有一个当前景别可见或当前音频可听的动作载体；
- 载体不违反用户硬约束；
- 同一策略只保留一个主要身体语法，避免同义动作重复；
- 反馈若不存在，不把角色自己的情绪变化伪装成对方回应。

交互任务额外检查：

- 实体许可按所有权判断，主角色自己的身体与外部对象没有混为一类；
- 硬排除已经通过首帧门禁；未通过时停止编译 Prompt；
- 隐藏对象后，动作不依赖不存在的持续支撑、重量、拉力或物体转移；
- 物体交换所需物体已经存在于首帧或作为输入素材明确绑定并获准保留，没有用“允许新增”替代存在性检查；
- `implied_contact_experimental` 只描述接触暗示，不声称对方真实完成动作；
- 起点、主路径、关键表面朝向、停点和收势足以区分易混淆动作；
- 实体排除和动作可读性分别有验收条件。

### 非模板性自检

在写 Prompt 前回答：

- 如果把情绪词删掉，动作是否仍然清楚地服务当前目标？
- 是否能从动作看出角色正试图影响谁、改变什么？
- 动作是否只对本场的具体刺激成立，而不是能贴到任何场景？
- 动作幅度是否符合 `style_contract`，而不是默认越小越好？

若任一为“否”，返回表演提升 Reference 重新选择或具体化 tactic。

## 4. 组装 Beat Graph

### 节点定义

- `baseline / expectation`：提供行动开始前的任务或期待，不必是中性脸。
- `trigger`：刺激必须能被观众定位。
- `orient/process`：即时定向或短处理，二选一；不机械添加延迟。
- `first_change`：第一次可辨认状态差。
- `action/control/redirect/choice`：tactic 的真正落实。
- `feedback`：对方、环境或行动结果提供的可定位反馈；可以明确缺席。
- `adjustment`：因反馈而坚持、升级、改道或停止。
- `threshold/release`：可选；短暂越过控制、认知或决定阈值。
- `end_state`：明确镜头最后由谁持有什么状态。

### 节点选择

- 参考图已有强起始表情时，不重复建立中性 baseline。
- 惊跳、威胁定向、身体失衡可即时反应；认知复核、克制与语言规划可有短处理。
- reveal 场景可直接行动；restrain / deny / redirect 才需要具体控制或改道。
- 只有反馈实际存在且时长允许时才加入 adjustment；简单场景可以在行动或等待中结束。
- 高潮不等于哭喊；行动风险增加、控制破口、策略改变、真相被接受或行动不可逆都可构成 threshold。
- end state 默认保留行动造成的新关系或任务状态，不回到开场状态，除非剧情就是恢复伪装。

## 5. 表演意图与通道预算

每个 beat 只安排一个主要表演意图。简单表演选择一个主通道，必要时加入一个可见辅助通道：

| 构图 | 优先可读通道 | 谨慎使用 |
|---|---|---|
| 特写 | 视线、笑意消失、嘴/下颌、说话边界 | 大幅身体动作、复杂走位 |
| 中近景 | 视线、嘴/下颌、上胸/肩、手、声音 | 脚步与精确全身重心 |
| 中景 | 手、姿态、距离、朝向、声音 | 极细眼睑或喉部动作 |
| 全身 | 重心、步伐、接近/退出、目标动作 | 极细微表情作为唯一信息 |

呼吸只有在上胸/肩可见或音频可听时才是有效指令。吞咽只有在喉部可见且临近说话边界时才可作为待测选择。眨眼通常不承担情绪信息；若剧情确需，只限定一次并放在说话或决定边界。

机械联动不按身体零件逐个计数：一次轻跳中的屈膝、离地、落地缓冲属于同一个 Motion Unit。若头、手、眉、嘴、重心分别承担探头、招手、挑眉、嘟嘴、蹦跳等独立任务，则属于动作并发，不是机械联动。此时按顺序处理：

1. 保留最直接服务 WANT 的主要行动；
2. 删除装饰性或重复表达的动作；
3. 能自然承接的动作改为串行；
4. 必须精确同步或完整保留时，交给对应模型的动作控制工作流。

Motion Unit 的机械拆解、速度、方向、接触与收势规则见 `references/kling-motion-control.md`。

交互动作还要按 `references/interaction-performance.md` 保留决定动作身份的最小签名。动作名称本身不能替代路径或表面朝向；若隐藏对象后识别度低、物理依赖无法消除，改为邀请等待或返回需求冲突，不能通过增加动作零件硬凑完成感。

## 6. 可观察语言

优先：

```text
fades / stops / stills / releases / returns / withdraws
begins to... then stops
prepares to... but chooses not to
once / one brief / for one beat / half a step
when... / only after... / after the unfinished word...
```

慎用：

```text
subtle / restrained / internal / realistic / emotional
```

这些词只能作为具体动作之后的幅度护栏，不能独立承担表演设计。

删除：重复情绪同义词、不可见比喻、无对象的环顾、无次数的紧张眨眼、互相竞争的动作和无法验证的精确秒点。

## 7. 时长预算

| 时长 | 主 beat 数 | 推荐责任 |
|---:|---:|---|
| 4–6 秒 | 2–3 | trigger、一次可见 tactic、end state |
| 7–10 秒 | 3–5 | 可加入 baseline、行动、反馈和一次调整 |
| 11–15 秒 | 5–7 | 可加入一次策略改道、恢复失败、短对白或听者反应 |

台词占用嘴部与时间预算。台词越长，越应删除面部零件指令或拆镜。

## 8. 证据边界

- 面部、身体、呼吸与情绪均为多对多关系。
- FACS 描述可见运动，不证明角色真实感受。
- “微表情”在本 skill 中仅指相对基线的短暂低幅度变化。
- 模型对精确微动作、负面约束、口型和时序的服从必须通过多次生成验证。
