# 质量门

生成最终答案前逐项检查。失败项必须修正后再输出。

## A. 语义与非模板性

- [ ] 用户关于人物、剧情、强度、空间、对白、镜头和模型的硬要求已先锁定，创作推导没有覆盖它们。
- [ ] 已按场景责任选择最低够用的 `analysis_depth`，简单表演没有被强行加入 stakes、潜台词或完整升级弧。
- [ ] 有明确 target、WANT 和 tactic；只有场景需要时才有 obstacle、stakes 或 HIDE/CONFLICT。
- [ ] tactic 指向对象并预期改变对象，不只是向观众展示情绪。
- [ ] trigger 能在画面或声音中定位。
- [ ] 至少内部比较过两个真正不同的 tactic，差异是影响对象的方式，不是表情、幅度或同义动作。
- [ ] 最终选择通过关系、角色专属性、style contract、镜头可读性和模型可执行性筛选。
- [ ] 删除情绪词后，动作仍能解释本场处境。
- [ ] 没有建立或调用固定的“情绪—动作”或“行动动词—身体动作”词典。
- [ ] 没有把视线、眉、泪、吞咽或姿态写成情绪真相指纹。

## B. 因果与节拍

- [ ] 每个关键动作能回答：因为什么、服务什么目标、改变了什么。
- [ ] 高潮来自行动风险、控制破口、策略变化或结果确认，不只是动作和表情变大。
- [ ] 回落来自反馈、主动结束或重新控制，没有机械恢复开场中性状态。
- [ ] 若写到“获得回应”，场景中存在可定位的对方反馈；否则已改为等待、继续争取或主动停止。
- [ ] 即时反应或短处理符合场景，不机械添加延迟。
- [ ] 每个 beat 只有一个主要表演意图；机械联动属于同一 Motion Unit，独立表达任务已删减、串行或转交动作控制。
- [ ] 时长容得下主 beats 与台词。
- [ ] 有明确 end state，或明确说明在 threshold 处切断。

## C. 镜头与互动

- [ ] 指令使用的动作在当前景别可见。
- [ ] 每个 beat 只有一个 reaction owner。
- [ ] 多角色的其他人有明确听、说、等待、继续任务或退出状态。
- [ ] 多镜头把上一镜残留带入下一镜。
- [ ] 镜头、灯光、环境没有抢占表演预算。
- [ ] 演员 Cut 的镜头前存在具体想象对象与预期效果，不是对摄影设备展示情绪。
- [ ] 剧情听戏中的具体刺激改变了听者下一步 tactic。

## C0. 镜头导演与 Camera Unit

- [ ] 已读取 `references/camera-direction.md`；环境模式没有虚构 target、WANT、tactic 或演员情绪。
- [ ] `camera_intent` 能说明镜头要改变的信息、关系、规模、注意力、节奏或导演视点，不只是“更电影感”。
- [ ] 内部比较过至少两种真正不同的观看策略；差异不是 push/dolly 等同义术语替换。
- [ ] 已主动判断静止或移动；静止有观看责任，移动有可定位 driver。
- [ ] 每镜只有一个 Camera Unit：起幅、触发、一个主运镜、必要构图修正、停止与落幅均可观察。
- [ ] 辅助 pan/tilt 只维持构图，没有承担第二个独立揭示。
- [ ] 航拍、俯拍、POV、手持或 oner 没有被当作完整路径；另有方向、主体关系与结束构图。
- [ ] 演员动作与镜头共用执行预算：复杂一方出现时另一方已经简化、串行或拆镜。
- [ ] narrative 的人物方向、镜头方向、出画方向和下一镜 screen direction 保持清楚。
- [ ] 图生视频若需大量首帧外未知空间、背面或遮挡后内容，已标记几何风险并简化、使用参考或保持实验状态。
- [ ] 已选择 `prompt | ui_control | start_end_frames | video_reference | custom_multishot` 中实际可用的执行来源；没有把人物 Motion Control 当成相机路径控制。
- [ ] UI Camera Movement 与正文没有规定冲突路径；Start/End Frames 没有被宣称为中间路径精确。
- [ ] Prompt 没有用器材、8K、胶片、导演标签、`cinematic / sweeping / blockbuster / masterpiece` 替代 Camera Unit。
- [ ] 默认输出已用一至两行给出镜头设计，且完整镜头行为已经写入可复制 Prompt。

## C1. 交互表演与实体可见性

仅在存在交互、身体接触、物体交换、镜头表面动作或实体硬排除时检查：

- [ ] 已区分 `interaction_class`、`target_visualization`、互惠程度、接触要求、外部支撑和隐藏后的可读性。
- [ ] 实体按所有权判断；主角色自己的身体没有被误判为外部对象，用户未限制时没有擅自隐藏其非动作手。
- [ ] 硬排除已经检查实际首帧；首帧不可检查或含禁用实体时已阻断 Prompt，并给出素材修正要求。
- [ ] 隐藏对象后，模型正文只渲染获准主体，没有虚构对方已经回应、靠近、接触、接住或完成交换。
- [ ] 持续接触和物体交换缺少必要对象时已改成邀请等待或需求冲突，没有使用单边拟态伪造物理完成。
- [ ] 物体交换所需物体已存在于首帧或作为输入素材明确绑定并获准保留；没有用 `new_entity_policy: allow` 替代存在性检查。
- [ ] `implied_contact_experimental` 只用于短暂、无需持续支撑且隐藏后仍有中等以上可读性的动作，并明确待验证。
- [ ] 动作签名写清起点、主路径、决定动作身份的表面朝向、停点与收势；易混淆动作已被识别并避开。
- [ ] 只用一条正向主体/背景契约，没有用重复的外部人物、其他手、影子、倒影和物体否定词替代动作设计。
- [ ] 实体许可与动作可读性分别出现在成功标准中；一项通过没有被当成另一项通过。
- [ ] Motion Control 没有被描述成实体排除工具。

## C2. 复杂动作

- [ ] 已判断动作是简单串行链、多个镜头任务，还是需要精确驱动。
- [ ] 跳跃、转身或复合手势包含可读的准备、主动作和收势/落地，而不只是动作名称。
- [ ] 方向、速度、幅度、支撑/接触和镜头关系只保留当前动作必要的信息。
- [ ] 中近景没有把不可见的脚步细节当作关键控制；需要地面接触时已调整景别。
- [ ] 没有用增加分段数量掩盖同一瞬间的动作并发。

## C3. 对镜眼神与情绪参考

- [ ] 对镜且伴随头部/身体运动时，使用建立对视、自然调整、重新对镜三个阶段，没有要求眼珠全程锁死。
- [ ] 需要清楚读取的表情或台词放在回正/落稳并重新对镜之后。
- [ ] 转头、目标表情与身份稳定要求已转换为最小充分的正脸、侧脸、目标表情或脸部视频参考建议。
- [ ] 没有把 Facial Element 描述成服装、发型、妆容或道具一致性控制。

## C4. 原地表演与根位移

- [ ] `root_motion: locked` 明确标为内部需求标签，没有伪装成 Kling 官方字段。
- [ ] 用户实测失败只按原模型、工作流和约束登记，没有把共现措辞写成已证明的单一原因。
- [ ] Prompt 开头已定义人物站定、足底持续承重和人物—镜头距离不变，后续没有用全身动作改写该主体运动状态。
- [ ] 局部动作具有明确方向；零位移要求下没有混入朝镜头靠近、远离或“回到原位”的前后路径。
- [ ] 只有用户明确接受更换工作流时才另给 Motion Control，没有跳过文本修复。
- [ ] 匹配 `[USER-K3-02]` 条件时使用已验证的文本修复；模型、工作流、景别或动作方向改变时重新验收。
- [ ] 其他 Standard 修复若没有官方依据或用户生成验证，已标注“待验证实验版本”，没有晋升为稳定规则。
- [ ] 本轮新增模型结论已登记到 `references/evidence-ledger.md`。

## D. 对白

- [ ] 说话者、原文台词和 delivery 紧邻。
- [ ] 有说话前动作；有意从半句切入时已说明。
- [ ] 只有命名 speaker articulates speech。
- [ ] 听者对具体刺激作出反应，而不是 NPC 凝视。
- [ ] 台词后有闭口与 aftermath。

## E. 模型适配

- [ ] Seedance 使用连续因果 prose 和相对时序，没有伪造精确镜内时间控制。
- [ ] Seedance 的简单 Camera Unit 使用文本；复杂路径优先绑定视频参考或标为实验，正文没有与参考竞争。
- [ ] Kling 将配置和 Prompt 正文分离，规划标签没有冒充官方字段。
- [ ] Kling 单镜优先一个主运镜；UI 控件、Start/End Frames、Custom Multi-Shot 与 Prompt 的职责已分离。
- [ ] Kling Standard/Omni 演员 Cut 情绪 Prompt 使用动态分段框架，时间从 0 连续覆盖总时长，标题时间前没有“约”；Motion Control 未套用该框架驱动动作。
- [ ] 分段边界根据本场动作负荷分配，正文已声明时间仅作节奏参考，并明确跨段连续、不停顿、不重置、不重新起势。
- [ ] Kling Custom Multi-Shot 每镜一个戏剧任务，逐镜时长总和等于总时长。
- [ ] Kling Motion Control 已提供动作来源、动作参考编排、Facial Element 计划和补充 Prompt；补充 Prompt 没有重复或冲突的动作时间线。
- [ ] Motion Control 素材不足时已明确缺口，并仅把 Standard 版本标为近似降级方案。
- [ ] 没有承诺完美口型、负面提示词服从或模型绝对优劣。

## F. 护栏

只加入当前场景需要的少量护栏。每条纯否定应尽可能转换为正向状态：

| 风险 | 正向替代 |
|---|---|
| 过度哭泣 | 一次成分打断句子；肩保持安静；峰值后进入明确余波 |
| 机械眨眼 | 删除 blink cue；必要时仅在决定边界一次普通眨眼 |
| 随机手势 | 双手保持任务位置，仅完成一次目标动作 |
| 持续盯视 | 为一次移视指定目标和回看/退出结果 |
| 对镜运动时锁眼 | 静止时建立对视；运动时在镜头区域内自然调整；回正或落稳后重新对镜 |
| 人物走近再退回 | 登记限定范围的用户实测；先重写主体运动状态，删除前后向路径和全身返回任务，只保留有方向的局部动作；匹配条件下使用 `[USER-K3-02]` 已验证组合 |
| 交互对象或外部手增生 | 先核对首帧和实体所有权；正文只保留获准主体及其动作，把实体排除标为待成片验证，不堆叠同义禁止词 |
| 交互动作被误读 | 补足决定动作身份的起点、路径、表面朝向、停点和收势；删除会导向敬礼、遮光、挥手或其他误读的竞争路径 |
| 隐藏对象后持续接触失真 | 改为发起邀请并等待，或判定需求冲突；不让角色对空气持续承重、拉扯或交换物体 |
| 听者嘴乱动 | 仅命名 speaker 发音；听者不产生 speech-like mouth cycling |
| 死脸 | 身体主要静止，但保留一次有目的的视线、手或肩部变化 |
| 情绪重置 | 结尾保持新的视线、距离、姿态或未完成任务状态 |
| 无意义推近 | 返回 camera intent；没有信息、关系或观看距离变化时使用有理由的静止 |
| 航拍泛化为扫过 | 分开角度/高度与实际路径，指定 camera subject、主轴和落幅 |
| 人物与镜头同时过载 | 保留承担剧情变化的一方，另一方改为固定关系、简单跟随或拆镜 |
| 运镜方向漂移 | 只保留一个主路径，写清起幅、方向、停止和落幅；辅助修正不承担第二任务 |
| 首帧外空间变形 | 标记几何扩写风险，减小位移、改用参考或保持实验版本 |

## G. 成片反馈

仅在评价成片、比较 Take 或根据结果修正时检查：

- [ ] 已读取 `references/performance-review.md`。
- [ ] 只有 Prompt 时只评价设计风险，没有宣称实际演技成立。
- [ ] 已依次区分需求偏差、模型伪影、表演策略、镜头设计、镜头执行与呈现干扰。
- [ ] 评价引用具体可观察时刻，不推断演员或角色真实感受。
- [ ] 已定位最先失效的 Beat，只修改该节点及其下游。
- [ ] 镜头问题已区分 camera design mismatch、camera execution artifact、subject-camera desync、scene geometry/identity failure 与 continuity failure，并定位最先失效的 Camera Unit 节点。
- [ ] A/B 条件不一致时已标记比较受干扰。
- [ ] 未使用综合演技分数；单次用户偏好没有被普遍化。
- [ ] 用户要求修正版 Prompt 时，已返回表演提升主流程，而不是只输出评价报告。

## H. Prompt 自足性与必写项

对每条输出的 Prompt 正文检查（`[USER-PROMPT-01]`）：

- [ ] **独立自足**：正文没有出现"承接上一段 / 反打 / 同一个夜晚 / 刚说完 / 上一个视频"等模型无法使用的叙事上下文；叙事连贯只用于内部设计。
- [ ] 需要连续性时，用**显式可见状态**（首帧、姿态、泪光、位置、未说完的话）表达，而不是引用上文。
- [ ] **场景/氛围/光已写全**：时空、氛围、光方向/冷暖、脸上明暗层次都在正文里。
- [ ] **可见生理信号已写全**：眼中湿润、泛红眼睑、唇部细微颤抖、呼吸节奏等"需清晰可见"的项已列出。
- [ ] 图生视频没有以"输入图已给场景"为由删掉氛围、光或可见信号；只省略首帧已提供的空间几何。

## 默认输出验收

最终回答必须包含：

1. 模式判断与必要假设；
2. 交互任务的处理方式，仅在适用时输出；
3. 一句话导演逻辑；
4. 一至两行镜头设计，包含起幅、驱动、静止或主运镜、落幅和执行方式；
5. 所需模型的可复制 Prompt，或明确的素材/物理冲突；
6. 三条可观察成功标准，按模式保留核心表演、交互与镜头要求；
7. 一条主要不确定性或调试建议。

分析保持简短。不要输出内部候选策略、完整检查表或证据论证，除非用户要求。
