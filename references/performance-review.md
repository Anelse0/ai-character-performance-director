# 成片表演反馈

仅在用户要求评价成片、比较多个 Take 或根据生成结果修正 Prompt 时读取。评价服务下一轮表演改进，不替代表演设计。

## 1. 先确认可评价范围

- 只有文字 Prompt：评价表演设计风险，不能宣称成片演技成立。
- 有单个成片：依据可观察时刻判断需求符合、模型执行和表演过程。
- 有多个 Take：先检查角色图、模型、工作流、镜头、音频、时长和 Prompt 差异；条件不同则标记比较受干扰。
- 看不见、听不清或缺少用户原始要求的部分使用“不可判断”，不要补想象证据。

## 2. 按层诊断

固定顺序：

1. `brief_mismatch`：人物、情绪结构、台词、位置、动作或 ending 不符合用户硬要求。
2. `model_artifact`：身份漂移、位移、口型、手部、额外实体、视线、时序或物理异常。
3. `performance_design`：target、WANT、tactic、反馈或策略变化不成立。
4. `presentation_confounds`：镜头、剪辑、音频、光线或构图影响观众读取表演。

前一层失败不自动否定后一层。例如人物发生非预期位移时，需求符合度可以失败，但仍可单独判断其眼神与关系行动是否成立。

## 3. 定位最先失效的 Beat

按 `已有期待 → 刺激 → 行动 → 反馈 → 调整 → ending` 检查：

- 刺激是否能被观众定位；
- 行动是否确实指向 target；
- 反馈是否真实存在，还是 Prompt 无依据地宣称“得到回应”；
- 调整是否由反馈引起；
- ending 是否保留行动造成的新状态。

只修改最先失效的节点及其下游。不要因为一次视线漂移重写角色动机，也不要因为策略不成立只增加表情强度。

### 交互任务的双验收

交互成片必须拆开判断：

1. `entity_compliance`：是否只出现实体契约允许的人物、身体局部、道具、影子和倒影；
2. `action_legibility`：角色动作是否被读成目标交互，而不是挥手、敬礼、遮光、推掌或其他动作；
3. `physical_plausibility`：隐藏对象后是否仍符合接触、支撑、重量、拉力和惯性；
4. `interaction_residue`：结尾是邀请、等待、接触暗示还是实际结果，是否与可见证据一致。

一个维度成立不代表其他维度成立。没有新增外部实体但动作无法读懂，属于动作载体/模型执行失败；动作清楚但出现禁用对象，属于需求偏差或模型伪影。先修最早失效维度。

## 4. 表演成立性

使用描述性结论：`成立 | 部分成立 | 不成立 | 不可判断`，不汇总综合演技分数。

判断以下内容：

- `action_logic`：关键行为是否有对象、目的和因果位置。
- `moment_to_moment_response`：刺激和反馈是否改变下一步行动。
- `character_and_style_fit`：选择是否符合角色、关系、剧情阶段和风格契约。
- `camera_readability`：表演载体是否在当前景别与声音条件下可读。
- `continuity_and_ending`：变化是否连续，结尾是否保留新的状态。

不以克制、外放、哭泣或表情标签的强弱单独判定好坏。表情可识别性与情绪真实性不能互相替代，证据边界见 `references/acting-craft.md` 的 `[ACT-RESEARCH-01]` 和 `[ACT-RESEARCH-02]`。

## 5. A/B 与用户偏好

尽量只改变一个表演策略或动作载体，其余生成条件保持一致。依次询问或记录：

1. 用户认为人物正在争取什么；
2. 哪一版更符合角色与场景；
3. 哪一版更可信或更有感染力；
4. 具体在哪一刻成立或出戏。

单次用户偏好只对当前角色、场景、模型、工作流和风格成立。只有用户明确报告实际生成结果，才可按 `references/evidence-ledger.md` 登记为限定范围的 `user_verified`；普通评价建议不得自动晋升为稳定规则。

短暂互惠动作的单边接触暗示，单次成功只记录该 Take。至少三次同模型、工作流、首帧、时长和 Prompt 的生成全部通过实体许可与动作可读性，才允许登记为限定条件下的稳定用户验证。

## 6. 默认反馈输出

保持简短：

1. `结论`：最主要的成立点或失败点。
2. `问题归属`：需求偏差、模型伪影、表演策略或呈现干扰。
3. `证据`：一个或两个具体可观察时刻。
4. `下一版修正`：只修改收益最高的一项。
5. `不确定性`：仅在证据不足或比较受干扰时输出。

若用户同时要求新 Prompt，完成诊断后返回 `references/acting-craft.md`，重新选择或修正 tactic，再由正常模型适配流程渲染。
